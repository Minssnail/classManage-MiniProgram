# 积分排行榜快照

定期把积分排行归档到 git，云端数据万一丢失时仍能还原每个人的积分。

```
backup/
  raw/       云开发控制台导出的原始数据 —— 含完整姓名、手机号、学号，已被 .gitignore 排除
  ranking/   脱敏后的排行榜快照 —— 提交进仓库
```

## 怎么做一次快照

**1. 从云开发控制台导出**

云开发控制台 → 数据库 → 依次选中集合 → 导出（格式选 **JSON**），保存到 `backup/raw/`：

| 文件 | 是否必需 | 说明 |
| --- | --- | --- |
| `students.json` | 必需 | 学生名单与所在班级 |
| `scoreRecords.json` | 必需 | 积分与考勤记录 |
| `semesters.json` | 可选 | 提供后显示学期名；缺失时以记录的日期区间代替 |

导出格式是 JSON Lines（每行一个文档），脚本也兼容普通 JSON 数组。

**2. 生成并提交**

```bash
node scripts/snapshot-ranking.js --commit   # 生成后自动提交
node scripts/snapshot-ranking.js            # 只生成，自己检查后再提交
git push
```

产物是 `backup/ranking/YYYY-MM-DD.md`，按「班级 → 学期」分组，每个班的每个学期各一份榜单，
当前学期与历史学期都会归档。同一天重复执行会覆盖当天的文件；内容没变化时 `--commit` 不会产生空提交。

## 脱敏规则

| 字段 | 处理 | 示例 |
| --- | --- | --- |
| 姓名 | 只留姓氏，星号数固定 | 王小明 → 王** |
| 学号 / 手机号 | 只留后 4 位 | 2000000000123 → …0123 |

同一班内后 4 位基本唯一，你对照名册就能还原到具体的人，但仓库里看不到完整身份。

## 这个快照能做什么、不能做什么

**能**：还原每个学生在各班各学期的总分及五类积分的分项，用来重建排行榜、核对争议。

**不能**：还原账号、密码、手机号、逐条记录的时间与理由。它是防止「成绩没了」，不是完整的系统备份。

## 更需要注意的事

数据全部丢失的现实原因不是误删，而是**云环境到期被回收**：

- 小程序未发布：免费环境 6 个月
- 小程序已发布：**到期时间变为上线后第 15 天**

到期前续上基础套餐（19.9 元/月）比任何备份都重要。快照只是最后一道防线。

如果要保留完整的可恢复备份，就把 `backup/raw/` 里的导出文件另存到网盘或移动硬盘——那些文件含完整个人信息，不要提交到仓库。
